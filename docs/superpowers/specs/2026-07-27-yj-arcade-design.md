# 《YJ 아케이드》 설계 문서

작성일: 2026-07-27
상태: 승인 대기 → 구현 플랜으로 진행

## 1. 목적

유준이(8세, 숙련 플레이어)가 **아이패드 웹브라우저에서 오프라인으로** 즐기는 캐주얼 게임 모음집.
플레이스토어의 "Offline Games / No WiFi Games" 류를 참고하되, 유아용이 아니라 실력·발견 요소가 있는 게임으로 만든다.

세 가지를 동시에 만족한다.

1. **메인**: 유준이 혼자 오프라인 킬링타임 (차·비행기·대기 시간)
2. **보조**: 아빠 vs 유준 2인 대전 몇 개
3. **실험**: AI(Claude Code 서브에이전트)로 게임을 양산하는 파이프라인 검증

## 3. 아키텍처

핵심 원칙: **셸(런처)은 개별 게임을 전혀 모른다.** 파일 하나 추가 = 게임 하나 추가.

```
100game/
  index.html
  manifest.webmanifest
  sw.js
  src/
    main.js
    shell/
      menu.js        게임 그리드 메뉴, 카테고리 탭, 최고기록 뱃지
      tile.js        타일 렌더링 (아이콘은 게임이 코드로 그림)
      session.js     게임 마운트/언마운트, 일시정지, 뒤로가기, 결과 화면
      records.js     하이스코어·플레이 횟수 저장
    core/
      loop.js        고정 dt 루프 (네온에서 이식)
      input.js       터치·키보드·게임패드 통합, 2P 입력원 (네온에서 이식)
      draw.js        네온 팔레트, 글로우, 텍스트, 도형 헬퍼
      audio.js       WebAudio 합성 효과음
      storage.js     localStorage 래퍼
      rng.js         시드 가능한 난수
      juice.js       화면 흔들림, 파티클, 히트스톱 (네온에서 이식)
    games/
      <id>.js        게임 1개 = 파일 1개 (27개)
  forge/
    contract.md      에이전트에게 주는 게임 모듈 계약서
    catalog.json     양산 큐 (게임별 5줄 스펙)
  tests/
    contract.test.js 전 게임 자동 적용 계약 테스트
    shell/*.test.js
    games/*.test.js  게임별 룰 단위 테스트
```

### 3.1 게임 모듈 계약

양산의 금형. 모든 게임이 이 형태를 지킨다.

```js
export default {
  id: 'neon-snake',             // 파일명과 동일, kebab-case
  title: '네온 스네이크',
  tags: ['action'],             // action | puzzle | defense | sports | quiz | versus
  players: 1,                   // 1 | 2
  color: '#ff2e88',             // 타일 테마 색
  archived: false,              // true면 메뉴에서 숨김 (삭제 대신 보관)
  controls: 'dpad+a',           // pointer | dpad | dpad+a | versus — 셸이 터치 오버레이를 이걸 보고 그림
  scoreOrder: 'high',           // high(높을수록 좋음) | low(낮을수록 좋음, 예: 최소 이동수)
  scoreLabel: '점수',           // 결과 화면 표기

  icon(ctx, size) {},           // 메뉴 타일 아이콘도 코드로 그림
  init(api) {},                 // 상태 생성
  update(dt) {},                // dt는 초 단위 고정 스텝
  render(ctx) {},               // 렌더만. 상태 변경 금지
  dispose() {}                  // 타이머·리스너 정리
}
```

`api`로 주입되는 것:

```js
{
  w, h,            // 캔버스 논리 크기
  input,           // input.p1 / input.p2 — {left,right,up,down,a,b, pointer:{x,y,down}}
  draw,            // 팔레트·도형·텍스트 헬퍼
  audio,           // audio.beep(freq, ms) 등
  rng,             // 시드 난수
  juice,           // shake(), burst(), hitstop()
  onScore(n),      // 현재 점수 보고 (셸이 HUD·하이스코어 처리)
  onGameOver(res)  // {score, win, winner} — 셸이 결과 화면 담당
}
```

셸은 `import.meta.glob('./games/*.js', { eager: true })`로 전부 자동 수집한다.
**등록 코드를 손댈 필요가 없다** — 에이전트가 파일 하나만 떨구면 메뉴에 뜬다.

### 3.2 셸 UX

- 메뉴: 그리드 타일(아이콘 + 제목 + 최고기록). 카테고리 탭 = 전체 / 액션 / 퍼즐 / 대전 / 퀴즈
- 아이패드 세로·가로 둘 다 대응. 터치 우선, 게임패드 동시 지원
- 게임 중: 우상단 일시정지 → 재개 / 다시하기 / 메뉴로
- 게임 오버: 점수, 최고기록 갱신 연출, 다시하기 / 메뉴로

## 5. 양산 파이프라인

1. `forge/catalog.json`에 게임별 스펙을 5줄로 적는다 — `id / 제목 / 조작 / 룰 3줄 / 승리·점수 조건 / 난이도 곡선`
2. **서브에이전트 1명 = 게임 1개.** `forge/contract.md`(계약서) + 기존 게임 2개(모범 예시)를 컨텍스트로 준다
3. 게이트 ①: 공통 계약 테스트 자동 통과 (섹션 7)
4. 게이트 ②: 아빠 30초 플레이
5. 게이트 ③: 유준이 플레이. 재미없으면 **삭제 대신 `archived: true`** (메뉴에서만 숨김, 재료로 보존)

게임끼리 의존성이 0이고 파일이 분리돼 있어 **여러 에이전트 동시 투입 가능**하다 (worktree 불필요).

2단계(선택): 이 흐름이 안정되면 `npm run forge -- "우주 장애물 피하기"` CLI나 `game-forge` MCP 서버로 포장 →
유준이가 직접 자기 게임을 만들어보는 단계로 확장.

## 6. 배포·오프라인

- **PWA**: `manifest.webmanifest` + `sw.js`(빌드 산출물 전체 프리캐시). 아이패드 사파리에서 홈화면에 추가하면 비행기모드에서 실행
- 정적 빌드(무의존성). GitHub Pages 또는 로컬 서빙 둘 다 가능
- 뷰포트: 세로·가로 대응. 논리 해상도 고정 + 레터박스 스케일링
- 입력: 터치 우선, 키보드·게임패드 동시 지원 (TV 확장 대비)

## 7. 테스트 전략

**계약 테스트** — `tests/contract.test.js`가 `games/*.js` 전부에 자동 적용:

- export 형태 검증 (필수 필드·함수 존재, id가 파일명과 일치, id 중복 없음)
- 헤드리스로 60초치 `update+render` 실행 → 예외 0
- `dispose()` 후 타이머·이벤트 리스너 누수 0
- `onScore`로 보고된 값은 유한한 숫자(NaN·Infinity·음수 아님). 점수 의미(누적 점수/생존 시간/최소 이동수)는 게임이 정한다
- `render`가 상태를 바꾸지 않음 (render 2회 호출 후 상태 동일)

**게임별 테스트**: 핵심 룰을 순수함수로 뽑아 단위 테스트 (충돌 판정, 점수 계산, 승리 조건, 퍼즐 정답 검증)

**셸 테스트**: 게임 자동 수집, 마운트/언마운트, 하이스코어 저장·복원, 일시정지·복귀

계약 테스트가 양산의 안전장치다. 에이전트가 만든 게임은 이걸 통과해야만 메뉴에 오른다.

## 8. 구현 순서

27개를 한 번에 만들지 않는다. 4단계로 쪼개고, 각 단계 끝에서 유준이 반응을 본다.

| 단계 | 내용 | 끝났을 때 |
|---|---|---|
| A. 뼈대 | `core/` 이식 + 셸(메뉴·세션·기록) + 계약 테스트 + PWA | 빈 메뉴가 아이패드에서 오프라인으로 뜬다 |
| B. 금형 검증 | 손으로 만드는 게임 2개 (`neon-snake`, `crossy-robot`) | 계약이 실제로 통하는지 확인. 이 둘이 에이전트용 모범 예시가 됨 |
| C. 양산 | 나머지 22개를 서브에이전트로 (퍼즐 → 액션 → 대전 순) | 메뉴가 24개로 채워짐 |
| D. 정예 | `arena-zero`, `robot-runner`, `police-chase` + AI 아트 | 간판 3개 완성, 총 27개 |

A와 B는 순차, C는 병렬, D는 C와 병행 가능하다.

## 9. 성공 기준

1. 유준이가 아이패드 비행기모드에서 앱을 켜고 **혼자 30분 이상** 논다
2. 27개 중 유준이가 **반복해서 다시 여는 게임이 5개 이상**
3. 아빠 vs 유준 대전 게임 중 최소 1개가 **"한 판 더" 소리를 끌어낸다**
4. 새 게임 1개를 서브에이전트로 추가하는 데 **사람 개입이 리뷰 뿐**이다 (파이프라인 검증)
5. 전체 빌드가 무의존성 정적 산출물로 유지되고 오프라인에서 완전 동작

## 10. 비목표 (YAGNI)

- 온라인 멀티플레이, 계정, 랭킹 서버 — 오프라인 전용
- 인앱 결제·광고 — 없음
- 네이티브 앱 스토어 배포 — PWA로 충분
- 기존 네온 테스트 챔버·농장 게임을 이 허브로 흡수 — 별도 유지
- 27개를 넘어서는 확장 — 1차 검증 후 별도 사이클
